Монитор раскрытий эмитентов облигаций

Сервис следит за документами эмитентов, чьи облигации лежат в портфеле клиента. Когда в отчётности появляется ранний признак проблем, клиент получает короткую карточку: что произошло, дословная цитата и ссылка на документ — без советов. Это замысел MVP, а не готовый продукт.

01Проблема

Частный инвестор держит высокодоходные облигации и узнаёт о проблемах эмитента по падению цены, когда выйти уже дорого. Рейтинг не спасает: у большинства эмитентов с техническим дефолтом его нет, а там, где он есть, пересмотр запаздывает.

При этом эмитент сам публикует тревожные документы: отчётность с ростом долга, заключение аудитора с оговоркой, сведения о нарушении условий кредитных договоров. Читать их по каждой бумаге портфеля частный инвестор не будет.

Что уже есть и чем мы отличаемся

Подписки на раскрытия существуют: бот Boomin, лента СКРИН, самодельные боты по e-disclosure. Они пересылают все сообщения подряд, и клиент тонет в рутине. Мы добавляем три вещи: отбор только тех событий, которые меняют кредитный риск; привязку к бумагам из портфеля внутри приложения брокера; дословную цитату, проверенную кодом.

02Зачем это брокеру

Ценность для клиента
Узнать о раннем признаке проблем раньше рынка и спокойно решить, что делать с бумагой, без чтения десятков документов.
Ценность для брокера
Меньше неожиданных убытков у клиентов и меньше претензий после дефолтов, выше доверие к облигациям как продукту.
Метрики
Доля держателей, получивших карточку раньше рыночного сигнала (устойчивого падения цены); обращения в поддержку после кредитных событий; удержание держателей облигаций через 90 дней после события. Исходный уровень снимаем на ретроспективе и в песочнице; цель пилота — опережение рынка хотя бы в половине событий.
Бизнес-модель
Бесплатно для держателей облигаций как сервис удержания; дайджест для аналитиков и риск-менеджмента брокера как внутренний инструмент. Главная статья затрат — лицензия на ленту раскрытий; цену запрашиваем до старта.
Бумаги, размещённые брокером
Те же правила, без фильтрации: карточка — это факт и цитата, а не оценка бумаги. Политику согласуем с комплаенсом заранее.

03Где хватает правила, а где нужен AI

Многие события эмитент публикует отдельными типами сообщений о существенных фактах по Положению Банка России 714-П, а часть данных уже есть в API брокера. Такие события ловит простое правило, без модели. AI нужен там, где сигнал ранний и спрятан в длинном свободном тексте.

Правило, без LLM Тип сообщения или поле API
  • неисполнение обязательств по выпуску
  • изменение кредитного рейтинга
  • требования владельцев о досрочном погашении
  • отчётность не вышла в срок по графику из API брокера
  • оферта, погашение, купон по календарю

Уведомить быстро и точно. Это и главный соперник AI в эксперименте.

LLM Ранний признак в тексте
  • оговорка аудитора о непрерывности деятельности
  • нарушение ковенантов — условий кредитных договоров — в примечаниях к отчётности
  • рост долга и падение покрытия процентов
  • судебные требования крупных кредиторов

Формулировки свободные, отчёты на десятки страниц. Ключевые слова дают шум: «реструктуризация» встречается и в плановых сообщениях.

05Как не стать инвестиционной рекомендацией

По Базовому стандарту инвестиционных советников Банка России (п. 1.1) рекомендацией считается и информация, которую клиент может разумно воспринять как данную с учётом его финансового положения, целей или допустимого риска. Поэтому формат ограничен с самого начала:

  • только факт, цитата и ссылка на документ; без оценок «высокий риск» и без слов «продайте» или «держите»;
  • карточка одинакова для всех держателей выпуска и не зависит от профиля клиента;
  • в карточке нет сроков оферты и призывов к действию — механику оферты клиент найдёт в общей справке приложения;
  • явная оговорка, что сервис не гарантирует полноту: пропущенный сигнал не должен выглядеть как обещание предупредить.

06Первый эксперимент

Гипотеза
Ранние признаки, найденные LLM, появляются раньше рыночного сигнала и раньше правила по типам сообщений.
Что считаем событием
Первый дефолт или технический дефолт, не устранённый за 10 рабочих дней, — по сообщениям о неисполнении обязательств.
Верная карточка
Карточка по эмитенту, пришедшая за 3–180 дней до события.
Рыночный сигнал
Средняя цена за 5 дней, взвешенная по объёму, упала на 10% и больше при минимальном обороте. Нужен только для замера опережения.
Данные
Понедельные данные по каждому эмитенту — только то, что было известно на ту дату. Контроль — эмитенты без событий, подобранные по сектору, доходности и объёму выпуска.
Чтобы модель не знала исход
Настройка на событиях 2024 года, тест на 2025–2026 годах с замороженными промптами. Цитаты могут выдать эмитента, поэтому главный тест — события после даты отсечки знаний модели.
С чем сравниваем
Главный соперник — правило по всем типам сообщений 714-П плюс ключевые слова; второй — сам рыночный сигнал. Оценку риска выпуска из API (risk_level) сравниваем только на живых данных пилота: её истории в API нет.
Метрики и пороги
Точность (доля верных карточек) не ниже 50% по нижней границе 95% доверительного интервала; медианное опережение рыночного сигнала от 14 дней; не больше одной ложной карточки в квартал на портфель из 15 облигаций; 100% цитат проходят сверку.

Событий немного: по нашей оценке, в тест попадёт 40–60 эмитентов. Поэтому решение принимаем по нижней границе интервала, а не по точечной оценке. Пороги — наши ориентиры, а не результат измерений.

07План на 11 дней

  1. До старта. Запрос доступа к ленте раскрытий через организаторов; ручная проверка опережения на 5 прошедших событиях.
  2. Дни 1–2. Справочник эмитент → выпуски, выгрузка данных API по облигациям, архив документов по выборке.
  3. Дни 3–5. Правило по типам сообщений, LLM-экстрактор, сверка цитат; разметка 100 документов.
  4. Дни 6–8. Ретроспектива на событиях 2025–2026 годов и сравнение с правилом.
  5. Дни 9–10. Карточка в прототипе приложения через MCP-сервер, дайджест аналитика.
  6. День 11. Демо и честный отчёт по метрикам. Если лицензии к старту нет — демо на вручную собранном корпусе из публичных документов.

08Риски и как проверяем их заранее

  1. Доступ к данным. e-disclosure закрыт для автоматического сбора, лента Интерфакса платная, а часть эмитентов раскрывается через другие агентства. Проверка — до старта узнать цену и охват лицензии; СПАРК не считаем запасным вариантом, это тот же поставщик.
  2. Нет опережения. Рынок может узнавать раньше документов. Проверка — ручная ретроспектива на 5 событиях до основной разработки.
  3. Ложные тревоги. Клиент продаёт здоровую бумагу с убытком. Проверка — точность на контрольной группе и лимит ложных карточек на клиента, а не на выпуск.
  4. Регуляторика. Карточку сочтут рекомендацией. Проверка — согласовать шаблон с комплаенсом до показа клиентам.
  5. Редкость событий. Держатель высокодоходных облигаций может получать карточку редко, и сервис забудут. Проверка — частота по портфелям в песочнице; при низкой частоте — дайджест вместо пушей.
